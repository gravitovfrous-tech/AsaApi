# Pickup — подбор своих структур в инвентарь

Плагин для **ARK: Survival Ascended** на базе **AsaApi**. Добавляет чат-команду, которая подбирает
структуры **своего племени** рядом с игроком и кладёт их в инвентарь.

```
/pickup              - подобрать всё рядом (радиус по умолчанию)
/pickup w            - только стены
/pickup f 10         - фундаменты в радиусе 10 фундаментов
/pickup w c 5        - стены и потолки в радиусе 5 фундаментов
/подбор с 8          - то же самое на русском
/pickup help         - список типов и справка
```

---

## Команды

| Команда | Описание |
| --- | --- |
| `/pickup`, `/подбор`, `/подобрать`, `/пикап` | подобрать структуры рядом |
| `/pickuphelp`, `/подборпомощь` | справка и список доступных типов |
| `/pickupreload`, `/подборперезагрузка` | перечитать `Pickup.json` (только для администраторов) |
| `pickup.reload` (RCON) | перечитать `Pickup.json` из консоли/RCON |

Все команды настраиваются в `Pickup.json`. Дополнительно регистрируются **варианты с другой раскладкой**:
`/зшслгз` (это `/pickup`, набранное в русской раскладке) и `/gjl,jh` (`/подбор` в английской раскладке),
поэтому команда срабатывает, даже если игрок забыл переключить язык ввода. То же работает и для аргументов:
`/подбор ц 5` понимается как `/pickup w 5`.

Синтаксис:

```
/pickup [тип1 тип2 ...] [радиус]
```

* **тип** — один или несколько типов структур (см. таблицу ниже). Если тип не указан, берутся типы из
  `DefaultCategories` (по умолчанию — всё).
* **радиус** — число в «фундаментах» (1 фундамент = 300 игровых единиц). Число с суффиксом `u`
  воспринимается как радиус в игровых единицах: `/pickup f 1500u`.
* Аргументы можно указывать в любом порядке: `/pickup 10 w` = `/pickup w 10`.

## Безопасность

* **Чужое не подбирается никогда.** Перед подбором сравнивается `TargetingTeam` игрока и структуры:
  если племена не совпадают, структура пропускается (игроку сообщается, сколько чужих структур осталось
  нетронутыми). Одиночные игроки (племя = 0) подбирают только своё.
* По умолчанию подбираются **только неповреждённые** структуры — как в ванильной игре.
* Проверяется, что структура возвращает предмет (`PickupGivesItem`), что она не уничтожена, не в режиме
  предпросмотра и что игрок жив.
* За одну команду подбирается не более `MaxStructuresPerCommand` структур, ближайшая — первой.
* Между командами одного игрока выдерживается пауза `CooldownSeconds`.

## Установка

1. Соберите решение `AsaApi.sln` (Release / x64) — сначала проект `AsaApi`, затем `Pickup`
   (зависимость уже прописана в решении).
2. Скопируйте содержимое `Plugins/Pickup/out/` на сервер в папку плагина:

   ```
   <папка сервера>/ShooterGame/Binaries/Win64/ArkApi/Plugins/Pickup/
       Pickup.dll
       PluginInfo.json
   ```

3. Запустите сервер. При первом старте рядом с `Pickup.dll` будет создан `Pickup.json` со стандартными
   настройками — его можно править и применять без перезапуска сервера командой `/pickupreload`
   или `pickup.reload` через RCON.

> `PluginInfo.json` обязателен: без него AsaApi не загрузит плагин. Файл копируется в `out/` автоматически
> при сборке.

### Требования

* AsaApi версии **2.03** (плагин собирается против этого SDK, `MinApiVersion` в `PluginInfo.json`).
* Visual Studio 2022 (набор инструментов v143, версия 14.39.33519 — как у ядра AsaApi).
* Интеграция vcpkg для MSBuild (`vcpkg integrate install`), плагин использует тот же манифест и триплет,
  что и ядро: `x64-windows-1439-static-md` из `AsaApi/vcpkg_custom_triplets`.
* Файлы исходников содержат кириллицу и компилируются с ключом `/utf-8` — он уже прописан в проекте.

## Конфигурация `Pickup.json`

Файл создаётся автоматически. Отсутствующие поля берутся из встроенных значений, поэтому обновлять
конфиг после обновления плагина не обязательно.

### `Settings`

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `Language` | `ru` | язык сообщений (`ru`, `en` или свой, добавленный в `Messages`) |
| `Commands` | `/pickup`, `/подбор`, `/подобрать`, `/пикап` | команды подбора |
| `HelpCommands` | `/pickuphelp`, `/подборпомощь` | команды справки |
| `ReloadCommands` | `/pickupreload`, `/подборперезагрузка` | команды перезагрузки конфига |
| `RconReloadCommand` | `pickup.reload` | команда RCON для перезагрузки конфига |
| `RegisterLayoutAliases` | `true` | регистрировать варианты команд в другой раскладке |
| `ReloadRequiresAdmin` | `true` | перезагрузка конфига из чата только для администраторов |
| `DefaultCategories` | `["all"]` | что подбирается, если тип не указан |
| `DefaultRadius` | `3` | радиус по умолчанию, в фундаментах |
| `MaxRadius` | `30` | максимальный радиус, в фундаментах |
| `FoundationSize` | `300` | размер одного фундамента в игровых единицах |
| `MaxHeight` | `0` | ограничение по высоте в фундаментах, `0` — искать во всей сфере |
| `CooldownSeconds` | `2` | пауза между командами одного игрока |
| `MaxStructuresPerCommand` | `300` | максимум структур за одну команду |
| `OnlySameTribe` | `true` | подбирать только структуры своего племени |
| `RequireFullHealth` | `true` | пропускать повреждённые структуры (ванильное правило) |
| `AllowDamagedStructures` | `false` | принудительно подбирать повреждённые структуры (см. ниже) |
| `IgnorePlacementTimeLimit` | `true` | обходить ограничение «подбор только сразу после постройки» |
| `UseVanillaAllowCheck` | `true` | дополнительно спрашивать у игры разрешение на подбор |
| `SkipEnvironmentStructures` | `true` | не трогать природные/пещерные структуры |
| `RequirePickupItem` | `true` | пропускать структуры, которые не возвращают предмет |
| `ReportForeignStructures` | `true` | сообщать, сколько чужих структур было пропущено |
| `OctreeGroups` | `["STRUCTURES"]` | группы серверного октодерева для поиска |
| `Colors` | зелёный / красный / жёлтый | цвета сообщений `[R, G, B, A]`, значения 0..1 |

Доступные `OctreeGroups`: `STRUCTURES`, `STRUCTURES_CORE`, `THERMALSTRUCTURES`, `TARGETABLEACTORS`,
`ALL_SPATIAL`. Можно указать несколько — результаты объединяются без дублей.

Взаимосвязь настроек:

* `IgnorePlacementTimeLimit: true` (по умолчанию) временно включает `bAlwaysAllowStructurePickup` на
  время выполнения команды, поэтому структуры можно подбирать в любой момент после постройки. Если
  выключить эту опцию и при этом оставить `UseVanillaAllowCheck: true`, игра будет разрешать подбор
  только в ванильном окне после постройки (или если `AlwaysAllowStructurePickup=true` в настройках
  сервера) — остальные структуры попадут в счётчик «недоступно для подбора».
* `AllowDamagedStructures: true` отключает проверку здоровья (`RequireFullHealth` в этом случае не
  применяется) и ставит хуки на `AllowPickupForItem`. Повреждённая структура вернётся в инвентарь
  в текущем состоянии.
* `UseVanillaAllowCheck: false` убирает дополнительную проверку игрой — подбор идёт быстрее, но
  ответственность за корректность полностью на плагине (племя, здоровье и наличие предмета при этом
  всё равно проверяются, если включены соответствующие опции).

### `Messages`

Тексты сообщений по языкам. Плейсхолдеры — `{0}`, `{1}`, … Ключи: `Usage`, `UnknownType`,
`InvalidRadius`, `Cooldown`, `Dead`, `NoTribe`, `NothingFound`, `Picked`, `LimitReached`,
`ForeignSkipped`, `Reloaded`, `ReloadDenied`, `Internal`, `CategoryCount`, `SkippedNone`,
`SkippedDamaged`, `SkippedNotAllowed`, `SkippedNoItem`, `SkippedFailed`, `SkippedOverflow`,
`SkippedHeight`. Если ключа нет для текущего языка, берётся английский текст, затем — имя ключа.

### `Categories`

Массив типов структур. Тип совпадает, если сработало **хотя бы одно** из `Flags` / `Classes` / `Patterns`
и **ни одно** из `ExcludeFlags` / `ExcludeClasses` / `ExcludePatterns`.

* `Id` — идентификатор (используется в `DefaultCategories`), всегда работает и как аргумент команды;
* `DisplayName` — название в справке и в отчёте игроку;
* `Enabled` — включать ли тип;
* `Aliases` — аргументы команды (сравнение без учёта регистра, кириллица поддерживается);
* `Flags` — битовые поля `APrimalStructure`: `bIsWall`, `bIsFloor`, `bIsFoundation`,
  `bIsFenceFoundation`, `bIsDoorframe`, `bIsBed`;
* `Classes` — нативные классы, проверяется наследование (`APrimalStructure`, `APrimalStructureDoor`,
  `APrimalStructureItemContainer`, …);
* `Patterns` — подстроки пути blueprint'а структуры, blueprint'а возвращаемого предмета и тега варианта
  (`Wall`, `Ceiling`, `Tek`, `Greenhouse`, …), регистр не учитывается.

## Как это работает

1. Позиция игрока → `GetAllActorsInRange(...)` по указанным группам октодерева.
2. Фильтр: `APrimalStructure`, живой и не уничтожаемый объект, своё племя, нужный тип, высота.
3. Сортировка по расстоянию, обрезка по `MaxStructuresPerCommand`.
4. Для каждой структуры: проверки (здоровье, наличие предмета, ванильное разрешение) и вызов
   `APrimalStructure::PickupStructure(true, PlayerController)` — предмет появляется в инвентаре игрока,
   как при обычном подборе.
5. Ограничение «подбирать можно только сразу после постройки» обходится временной установкой
   `AShooterGameMode::bAlwaysAllowStructurePickup`, которая возвращается в исходное состояние сразу после
   выполнения команды (настройки сервера это не меняет).
6. Режим `AllowDamagedStructures` подменяет результат `AllowPickupForItem` у пяти нативных классов
   (`APrimalStructure`, `Door`, `Bed`, `Seating`, `BearTrap`) **только на время выполнения команды и только
   для structures своего племени**. Хуки ставятся лишь когда опция включена. Повреждённая структура
   возвращается в инвентарь с текущим состоянием — используйте с осторожностью.

## Известные ограничения

* Структуры, у которых нет blueprint'а возвращаемого предмета (например, некоторые системные объекты),
  пропускаются — их нельзя подобрать и ванильным способом.
* Поиск идёт по серверному октодереву: очень большие базы на границе выгрузки могут быть найдены не
  полностью.
* Каскадное уничтожение (когда игра вместе со стеной убирает прикреплённые к ней структуры)
  обрабатывается: уже уничтоженные объекты пропускаются, счётчик «сбой подбора» растёт только при
  реальном отказе.
